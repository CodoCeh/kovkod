# Границы и швы

Решено здесь, чтобы первый исполнитель не придумал шов, который остальные будут
переоткрывать.

## Кто где живёт

| Кусок | Где лежит | Кто трогает |
|---|---|---|
| Состав образа, пакеты, ярлыки стола | `tools/mkimage.sh` | задачи по офису, играм, виду |
| Настройки XFCE | `reference/xfconf/*.txt` → `tools/xfconf-dump-to-xml.py` | задача по виду |
| Белый список путей в образе | `tools/mkimage.sh` (манифест) + `tools/checkimage.sh` | все, кто добавляет файлы |
| Каталог магазина | `store/catalog.json` | задача по играм |
| Логика магазина | `store/backend.py`, `store/codoceh-store.py` | задача по прогрессу установки |
| Проверка магазина | `store/test-store.sh` | задачи по магазину и по рычагу |
| Проверка на устройствах | `tests/e2e/*.sh` | задачи по Android, кузнице, замеру |
| Экран сборки | `app/src/main/java/ru/codoceh/stol/setup/` | задача по снимку кузницы |

## Швы, которые нельзя ломать

**Настройки XFCE идут только через дампы.** Никто не пишет `xfce4-panel.xml` руками:
дамп снимается с живого стола, кладётся в `reference/xfconf/`, сборка раскладывает его в
образ, а `checkimage.sh` доказывает обратным чтением. Ручной XML не проверяется ничем.

**Каталог магазина — данные, а не код.** Новая игра — строка в `store/catalog.json`.
Категории берутся из каталога; захардкоженный список категорий в окне магазина — дефект,
а не интерфейс.

**Установка вызывается списком аргументов.** `backend.install_command()` сейчас отдаёт
строку для оболочки. Любая задача, добавляющая поиск по apt или пользовательский ввод,
обязана сначала перевести вызов на список аргументов — иначе это инъекция команд.

**Готовность стола определяется подключением к маячку 5910.** Не через `/proc/net/tcp`:
сокеты программ внутри образа оттуда из-под adb не видны, хотя порт открыт. К порту 5901
не подключаться вовсе — недочитанный баннер RFB заносит петлю в чёрный список TigerVNC.

**Части стола запускаются разом, сессии нет.** `start-gui.sh` поднимает xfwm4,
xfsettingsd, панель и рабочий стол одновременно; `stop-gui.sh` гасит их по списку из
`xfce.pids` и по шаблонам. Кто добавляет новую часть стола — добавляет её в оба места.

## Как трогать устройство из проверки

Ввод на столе доступен через Android: `adb shell input tap X Y` попадает в приложение, а
оно переводит касание в событие указателя RFB. Это единственный путь нажать на что-то
внутри стола снаружи — прямого доступа к X-серверу с хоста нет.

Координаты считать от размеров стола (1600×1000) с поправкой на то, как приложение
вписывает картинку в экран телефона. Слепые числа в проверке запрещены: если координата
не выведена из состояния экрана, проверка доказывает случайность.

## Среда: чему нельзя верить под proot

Смотри раздел в `AGENTS.md` — он писался кровью прошлых прогонов. Коротко: `[ -r ]` и
`[ -x ]` врут; ранний обрыв конвейера убивает пишущую сторону; первое `apt-get update`
нестабильно; аппаратного ускорения нет; `grep` в списке процессов находит сам себя, если
шаблон не спрятан в скобки.

## Добавлено этим прогоном

**Подмены /proc лежат рядом с образом, а не внутри.** `ProotSession` создаёт
`files/procfake/` и привязывает оттуда файлы в `/proc`. Кто добавляет новую подмену —
кладёт туда же. Обвязка проверок подмену НЕ делает: иначе доказывала бы себя, а не
раздаваемый APK.

**Стек windows-программ — по требованию, не в образе.** Ставится тем же путём, что
программы магазина. В раздаваемый APK не попадает: запаса по весу 38 МБ, а стек тяжелее.

**Диагностика пути щелчка.** `tests/e2e/click-path.py` говорит с X-сервером напрямую по
сокету: маска нажатых кнопок, захват указателя, окно под курсором, время прихода событий.
Начинать расследование ярлыков с него, а не заново.
