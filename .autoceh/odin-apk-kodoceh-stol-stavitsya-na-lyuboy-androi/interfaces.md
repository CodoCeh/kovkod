# Швы

Границы решены здесь, чтобы первый исполнитель не придумывал их за остальных семь.

## Карта

```
Android APK  ru.codoceh.stol
├── setup/    мастер первого запуска  ──> RootfsInstaller
├── runtime/  запуск и остановка стола ──> ProotSession
├── screen/   встроенный клиент VNC (на основе AVNC)
└── assets/   rootfs.tar.zst + image.json + бинарники arm64 + apps.json + лицензии

Сайты производителей
└── только проприетарные программы, при первом запуске
```

## Шов 1: приложение ↔ образ в assets

Образ лежит в самом APK. Сети на этом шаге нет вообще.

```json
{
  "version": "2026.08.1",
  "asset": "rootfs.tar.zst",
  "sha256": "…",
  "bytes": 419430400,
  "unpacked_bytes": 2147483648,
  "min_android": 28
}
```

Правила: сумма проверяется **до** распаковки; распаковка идёт в `files/rootfs.partial` и
переименовывается в `files/rootfs` последним шагом. Незавершённая установка обязана быть
отличима от завершённой по наличию `files/rootfs/.stol-ready` — метка ставится последней
операцией, после переименования.

## Шов 2: приложение ↔ Linux внутри

Ровно одна функция запуска команды в образе:

```
ProotSession.exec(command: String, background: Boolean): Int
```

Всё, что приложению нужно от Linux, проходит через неё. Прямых вызовов `proot` из
остального кода нет. Внутри образа лежат два скрипта, и приложение знает только их имена:

- `/opt/stol/start-gui.sh` — поднимает Xtigervnc `:1` и XFCE, затем маячок готовности;
- `/opt/stol/stop-gui.sh` — гасит сессию и маячок.

## Шов 3: готовность стола

Два порта на `127.0.0.1`, оба только для локальных подключений:

- **5901** — RFB. Отвечает сразу после старта X, к готовности стола отношения не имеет.
- **5910** — маячок. Открывается скриптом только после того, как в списке окон есть и
  панель, и стол.

Клиент подключается **после** 5910, а не после 5901. Это и есть лечение чёрного кадра;
обкатано на эталонном столе.

## Шов 4: список программ

`assets/apps.json` — данные, не код. Приложение их только исполняет.

```json
[
  {
    "id": "vscode",
    "name": "Visual Studio Code",
    "kind": "deb",
    "url": "https://update.code.visualstudio.com/latest/linux-deb-arm64/stable",
    "icon": "code",
    "desktop": "code.desktop"
  },
  {
    "id": "zcode",
    "name": "ZCode",
    "kind": "appimage-extract",
    "url": "https://cdn-zcode.z.ai/zcode/electron/releases/3.7.7/linux-arm64/ZCode-3.7.7-linux-arm64.AppImage",
    "target": "/opt/zcode-app",
    "exec_flags": "--no-sandbox --disable-gpu --disable-software-rasterizer --disable-dev-shm-usage"
  },
  {
    "id": "gemini",
    "name": "Gemini",
    "kind": "webapp",
    "url": "https://gemini.google.com/app",
    "profile": "/root/.config/gemini-app"
  }
]
```

Виды установки — закрытый список: `deb`, `appimage-extract`, `webapp`, `apt`. Новый вид
добавляется кодом; новая программа — строкой в файле.

Вид `webapp` и `apt` ставятся из образа и сети производителя не требуют — так живёт
Gemini (Chromium уже в образе). Виды `deb` и `appimage-extract` — единственные, кому
нужна сеть, и это ровно шесть проприетарных программ.

Установщик обязан вернуть по каждой программе одно из трёх: `installed`, `failed` с
причиной, `skipped-offline`. «Адрес ответил» состоянием не является.

Флаги Electron под proot (`--no-sandbox --disable-gpu --disable-software-rasterizer
--disable-dev-shm-usage`) обязательны и проверены на эталоне — без них окна не появляются.

## Шов 5: сборка образа ↔ проверка образа

`tools/mkimage.sh` собирает, `tools/checkimage.sh` проверяет **по белому списку**, а не по
чёрному: рядом с образом лежит `manifest.txt` — перечень ожидаемых путей в `/root` и
`/home`. Проверка падает на любом пути, которого в перечне нет.

Чёрный список ловит только то, что кто-то заранее вспомнил; белый ловит и то, чего никто
не ждал. Отдельными правилами, поверх белого списка, падаем на:

- непустых `/root/.bash_history` и журналах;
- `/etc/hosts` и `/etc/resolv.conf`, отличных от эталонных;
- любых каталогах `.git`;
- файлах шести проприетарных программ.

Проверка запускается в каждом прогоне и служит доказательством по R05, R06 и R12i.

## Шов 6: эталон

`reference/` в репозитории — снятый с Galaxy Fold дамп: `wallpaper.png` с суммой, вывод
`xfconf-query` по четырём каналам, список `.desktop`, скриншот. Сверка результата с этим
дампом — доказательство по R07 и R08. Дамп снимается один раз и коммитится; личных путей
в нём быть не должно, это проверяет та же `checkimage.sh`.
